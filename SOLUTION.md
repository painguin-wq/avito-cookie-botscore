# Решение

Python 3.13.14, pandas 3.0.6, numpy 2.5.3, scikit-learn 1.9.1, lightgbm 4.7.0.
Это open-source библиотеки, запуск локальный, внешние API не используются.
random_state=42.

Воспроизведение: pip install -r requirements.txt, затем solution.ipynb.
Тот же итоговый вариант считает python solve.py и пишет submission.csv.

Признаки только из событий внутри окна cookie. Валидация: window_start с 17 апреля.

В сабмите LightGBM bag из пяти сидов на агрегатах окна, peer-ranks и признаках catalog-crawl.
Параметры num_leaves 48, min_child_samples 60, colsample_bytree 0.9.
На валидации Precision при Recall 70% равна 0.857, без пакета catalog-crawl было 0.713.

Target encoding по item_id не используется. Частота объявления считается без лейбла по событиям train и test.
Дубликаты событий не удаляются, их число входит в признаки.

## Валидация

Базовый LightGBM на поведении и peer-ranks даёт 0.7125. На пороге Recall 70% примерно 114 true positive, 46 false positive и 46 false negative.

Кластер молодых web-кук с глубокой выдачей уже целиком в true positive. Ошибки остаются в середине списка: mix и mobile дают ложные срабатывания, короткие сессии дают пропуски.

## Пакеты признаков

catalog-crawl 0.830 за счёт длины серии страниц с шагом +1, числа объявлений на поиск, item_uniq у новой куки и частоты item без лейбла.
human_trace 0.727.
pointer_flag и power_crawler 0.709.
dt_entropy 0.667, пакет ухудшает метрику.
Все новые признаки сразу 0.818, ниже чем catalog-crawl отдельно.

Pointer на mobile не заполняется медианой.

## После catalog-crawl

Рабочий набор это база плюс catalog-crawl.

bag и сетка 48/60/0.9: 0.857
двухступенчатая схема с той же сеткой: 0.857 при более низком PR-AUC
bag на исходных гиперпараметрах: 0.852
один LightGBM 48/60/0.9: 0.850
веса на сложных ошибках: 0.831
понижение score активных залогиненных пользователей: 0.825-0.830
раздельные модели web и mobile: 0.806
база: 0.713

Двухступенчатая схема использует правило молодая кука, page не ниже 16, locs не ниже 12, без логина, web. Оценка острова стоит выше, LightGBM ранжирует остальные cookie. Recall правила небольшой, середину ранжирует вторая ступень. В файл записан bag.

Сетка подбиралась по Precision при Recall 70%, без оптимизации logloss. Калибровка вероятностей и случайный шум на совпадающие score не использовались.

## Что не сработало

GWO, сжатие Lasso, MLP-экстрактор и среднее трёх бустингов на предыдущем прогоне были ниже полного LightGBM.
Target encoding по item протекает.
IsolationForest, понижение score по Mac и правила как основной скор тоже не улучшили метрику.
dt_entropy портит Precision при Recall 70%.
Разделение web и mobile лучше по PR-AUC и хуже по целевой метрике.

Короткие мобильные сессии остаются среди пропусков, потому что за сутки по ним мало сигнала. Дальнейшая подстройка под три дня валидации повышает риск переобучения.
